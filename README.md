## Структура папки практики

Одно задание - одна папка `task-N-<о чем>`. Все, что по нему сдается, лежит
внутри целиком: преподаватель открывает папку задания и видит ровно то, что
к нему относится, а прикреплять можно папку целиком, не собирая файлы по
разным углам.

```
ГГГГ-ММ-ДД-название/
├── README.md            ответы по каждому заданию
├── task-1-erd/
│   └── erd.pdf          ER-диаграмма
├── task-2-schema/
│   ├── schema.sql       DDL: DROP + CREATE + ограничения
│   └── screenshots/     подтверждение выполнения
├── task-3-etl/
│   ├── raw/             исходники как выданы, без единой правки
│   ├── *.csv            подготовленные данные
│   ├── import.sql       загрузка + проверочные COUNT
│   └── screenshots/     подтверждение выполнения
└── task-4-queries/
    ├── queries.sql      запросы по заданию
    └── screenshots/     подтверждение выполнения
```

Снимки экрана кладем в `screenshots/` внутри задания и вставляем в README
картинками - там, где задание требует показать результат выполненным, а не
только код. Открываются прямо в README, отдельно прикреплять нечего.

Имена папок и их число зависят от условия конкретной практики - совпадать с
этим примером они не обязаны. Неизменны только номер в начале (сортировка) и
правило «все по заданию внутри».

Папка `_template` - заготовка для новой практики: скопировать, переименовать, заполнить.

## Соглашения

- Имена файлов и папок - латиница, нижний регистр, дефисы. Ни пробелов, ни кириллицы: в URL они превращаются в `%D0%9F%D1%80%D0%BE...` и ссылки становятся нечитаемыми.
- Дата в начале имени папки - практики сортируются по порядку сами.
- СУБД по умолчанию - PostgreSQL. Если в конкретной практике другой диалект, это указано в ее README.
- Бинарные дампы (`.backup`, custom format) в репозиторий не кладем - только текстовый SQL, который открывается в любом редакторе.
- Исходные файлы задания кладем в подпапку `raw/` внутри папки задания и не правим никогда, даже переводы строк (это закреплено в `.gitattributes` шаблоном `**/raw/**`). Очистка описывается в README практики, а проверить ее можно только при живом исходнике рядом.
- Скрипты должны переживать повторный запуск: `schema.sql` начинается с `DROP TABLE IF EXISTS`, вставки в `queries.sql` - через `ON CONFLICT`. Проверяющий запустит файл дважды.
