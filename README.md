## Структура

Требование преподавателя к структуре директорий:

```
Учебная практика/
└── Учебная практика_ГГГГ-ММ-ДД/
    ├── README.md                     обзор практики
    ├── <название задания>/
    │   ├── README.md                 ответ по заданию
    │   ├── ...                       файлы задания
    │   └── screenshots/              подтверждение выполнения
    └── <название другого задания>/
        └── ...
```

В ответе на задание дается ссылка на директорию самого задания.

Имена папок практик и заданий пишутся по-русски, по этому шаблону. Папка задания
называется дословно так, как задание озаглавлено в условии, без номера: проверка
идет по названию. Порядок папок при этом алфавитный, а не по номерам заданий.
Файлы внутри называются латиницей (`schema.sql`, `discount.py`): их имена стоят
в коде и в командах запуска.

Дата пишется в ISO, `ГГГГ-ММ-ДД`. Формат шаблон не задает, а в `ДД.ММ.ГГГГ`
сравнение идет сначала по дню, и сортировка по дате ломается.

Если задания складываются в одну программу, модули все равно раскладываются по
папкам заданий. Папки с пробелами не могут быть пакетами Python, поэтому модули
соседних заданий подключаются через `sys.path`. Пример - практика 2026-09-14,
файлы `conftest.py` и `main.py`.

Снимки экрана кладем в `screenshots/` внутри задания и вставляем в README
картинками там, где задание требует показать результат выполненным, а не
только код.

Папка `_template` - заготовка README для новой практики.

## Соглашения

- В ссылках Markdown путь с пробелами берется в угловые скобки: `[текст](<./Название задания>)`, иначе GitHub ссылку не распознает.
- СУБД по умолчанию - PostgreSQL. Если в конкретной практике другой диалект, это указано в ее README.
- Бинарные дампы (`.backup`, custom format) в репозиторий не кладем - только текстовый SQL, который открывается в любом редакторе.
- Исходные файлы задания кладем в подпапку `raw/` внутри папки задания и не правим никогда, даже переводы строк (это закреплено в `.gitattributes` шаблоном `**/raw/**`). Очистка описывается в README задания, а проверить ее можно только при живом исходнике рядом.
- Скрипты должны переживать повторный запуск: `schema.sql` начинается с `DROP TABLE IF EXISTS`, вставки идут через `ON CONFLICT` или перезаливку. Проверяющий запустит файл дважды.
